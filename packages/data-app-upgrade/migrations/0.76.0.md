# Upgrade to SDK 0.76.0

Calendar views now use datetime ranges. Replace calendar variables with
`dateTimeRangeVariable()` and direct `<DateRangePicker>` calls with
`<DateTimeRangePicker>`. Update operation input and defaults to use `from`
and `to`.

An old inclusive end date becomes the start of the following day in the
reporting timezone. Update SQL predicates to use `>= from` and `< to`.
Check the final selected day, timezones, and previous-period comparisons.
Legacy date-only URLs need new datetime selections.
Review form serialization and custom picker props if the app used the picker
directly. This release has no automatic source edits.

See the [datetime migration diff](https://github.com/altertable-ai/data-app/commit/384683362a2ef934ee43993c36a8be2efab6788e).
