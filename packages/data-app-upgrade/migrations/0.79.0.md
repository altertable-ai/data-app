# Upgrade to SDK 0.79.0

`@altertable/data-app-react/ui` no longer exports `DataApp`, `DataValue`,
`MetricWidget`, `TableWidget`, `TextWidget`, or `VisualizationWidget`. Each of
these names now has one meaning: the component from `@altertable/data-app-react`
that binds to a view. Replace each `/ui` import:

- **Fetched or computed values.** Return them from an operation, define a view,
  and pass its dataset or metric and the view's `source` to the widget. An
  operation that returns literal data needs no query.
- **A custom or static visual, table, or prose.** Frame it with `<DataWidget>`
  from `/ui`, using `<DataTable>` or `<TextContent>` inside.
- **A setup or static screen.** Render `<DataApp>` from
  `@altertable/data-app-react` with a `dataContext` and no `view`.
- **Direct CSV data or disclosed queries on `<DataApp>`.** Pass the view's
  `datasets` instead; exports and inspection derive from the displayed result.
  Export filenames now derive from the dataset or app title and the displayed scope.

A view whose operation returns a row array is empty when it has no rows.
Previously a view without `isEmpty` was never empty. Review views that omit
`isEmpty`: set `emptyFallback` copy for the empty state, or pass
`isEmpty: () => false` to keep rendering widgets with no rows.

The following additions need no change. Datasets may omit `select` when the
operation returns rows, and a column named after a row field may omit `value`.
`dataApp.queryNames` lists every registered query name. An operation's
`policy.maxDurationMs` has a default.

This release has no automatic source edits.
